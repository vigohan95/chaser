# Reconciliation benchmark

Generated by `npm run bench:recon` from [`tests/fixtures/recon-bench.json`](../tests/fixtures/recon-bench.json): 81 invoices, **71 labelled transactions** across 15 scenario types (exact, partial, split across several invoices, net-of-fee, memo typos, duplicates, refunds, overpayments, ambiguous pairs, wrong currency, off-invoice payments). The matcher is [`src/lib/agent/reconcile.ts`](../src/lib/agent/reconcile.ts); the scorer is [`src/lib/agent/recon-bench.ts`](../src/lib/agent/recon-bench.ts) and [`tests/recon-bench.test.ts`](../tests/recon-bench.test.ts) pins these numbers.

A transaction is **correct** only when the predicted rule *and* the full allocation set (invoice numbers and amounts) equal the label. Precision = correct / predicted for that rule; recall = correct / labelled for that rule.

**Overall: 70 / 71 correct (98.6%).** Of the 53 transactions the matcher would record without a human (`record_payment` / `record_refund` actions), 53 are correct (**100% auto-record precision**); `review` matches (ambiguous, amount-only, duplicate) are shown in the match review and never recorded by the agent.

## How the fixture is built

`scripts/gen-recon-bench.ts` writes the fixture deterministically (fixed `now` = 2026-10-13, transaction ids derived from the scenario name) so the labels are reviewable in the diff. Scenario types and counts:

- `memo_exact`: 8
- `memo_other_payer`: 3
- `partial_memo`: 4
- `payer_exact`: 10
- `fee_adjusted`: 6
- `combined`: 6
- `partial`: 6
- `overpayment`: 3
- `ambiguous`: 4
- `duplicate`: 4
- `refund`: 5
- `amount_only`: 3
- `currency_mismatch`: 3
- `repeat_instalment`: 2
- `off_invoice`: 4

Known limits, on purpose: a legitimate second payment of the same amount within three days with no memo is reported as a duplicate for review (not recorded); a payment that fits two invoices equally is ambiguous (shown, not recorded); a net-of-fee payment is recorded at the net amount, leaving the fee gap on the invoice for the user to write off.
